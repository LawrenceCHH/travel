# 文章模板：先寫架構，後填內容

這個目錄放「已抽好架構、只等填內容」的文章模板，目的是把「寫文章」拆成兩個獨立步驟：

1. **使用者準備內容**——原始行程資訊、景點描述、美食清單等，不需要懂 Markdown 或任何卡片語法。
2. **Agent 負責把內容填進模板**——依模板裡的佔位符與結構規則，產出一篇可直接放進 `src/posts/`
   的完整文章。

模板本身只定義「架構」（有哪些區塊、每個區塊的欄位、重複規則），不含任何實際文字內容。

## 目前的模板

| 模板檔案 | 對應風格 | 抽取來源 |
| --- | --- | --- |
| `travel-itinerary-editorial-card.md` | `style: editorial-card` | `src/posts/2026-07-16-首爾秋日漫遊手帳.md` |

`travel-itinerary-editorial-card.md` 適合「多天行程、按景點分段、每段有友善度／休息建議，
文末附分區美食清單」這種手帳型遊記。若行程性質差很多（例如單日城市漫步、無明確景點分段），
不要硬套這份模板，改參考 `doc/card_dsl.md` 從零挑選合適的 fence 家族。

## Agent 填內容時的完整流程

1. 複製 `travel-itinerary-editorial-card.md` 到 `src/posts/YYYY-MM-DD-文章slug.md`
   （檔名格式與規則見 `doc/project.md` 第一部分「如何新增與編輯內容」）。
2. 依使用者提供的內容，逐一取代檔案裡的 `{{...}}` 佔位符：
   - Front matter：標題、副標題（出發地/目的地機場代碼、日期區間、天數）、封面圖、`tags`。
   - `總覽`：一句話行程調性 blockquote；`quickjump` 條目數必須等於下方 `stop` 區塊總數，
     且 `#spot-N` 順序要與 `stop` 出現順序一一對應。
   - `景點漫遊`：每天一個 `### Day N` 標題；每個景點一個 `stop` 區塊，`level` 只能填
     `diet`/`flat`/`slope`/`steps` 四選一（意義見模板內註解與 `doc/card_dsl.md` 注意事項）。
   - `美食推薦`：每個區域一個 `### [區域名](連結)` 標題，底下放該區域的美食卡；美食卡的
     觸發條件（單一連結標題＋緊接純 code span 段落）必須完整符合，否則不會渲染成卡片。
3. **填完後刪除模板裡所有 `<!-- -->` 說明註解**（它們是給 Agent 看的填寫規則，不是文章內容；
   HTML 註解不會被渲染，留著也不會壞版面，但正式文章不應保留）。
4. 執行 `npm run build:metadata`（或啟動 `npm run dev` 自動監聽）確認文章被正確索引；
   在瀏覽器打開文章頁，確認 `quickjump`／`stop`／美食卡三種區塊都渲染成卡片，而非原樣顯示
   fence 語法或程式碼區塊。
5. 依 `CLAUDE.md`「Mandatory after every code change」規範，若這次新增文章之外還動到程式碼、
   架構或本模板本身，記得同步更新 `doc/project.md` 的更新歷史與待辦事項。

## 相關文件（欄位語法的唯一真實來源）

模板裡的佔位符只標記「這裡要填什麼」，完整語法規則、每個欄位的合法值、觸發條件的判斷邏輯，
一律以下列文件為準，模板不重複抄寫：

- [`../doc/card_dsl.md`](../doc/card_dsl.md) — `quickjump`／`stop` fence 語法＋美食卡純
  Markdown 形狀規則（§2 `stop` 語法、§1.1 美食卡）。
- [`../doc/doc_style.md`](../doc/doc_style.md) — 標題階層與 `---` 分隔線使用規則。
- [`../doc/style.md`](../doc/style.md) — `editorial-card` 風格的視覺系統與跨文章共用前提。

## 新增其他風格的模板

若未來要為別種文章風格（非 `editorial-card`）建立模板，先確認該風格是否已有穩定的 DSL 家族
組合可抽取（參考 `doc/card_dsl.md` §4「文章視覺風格系統」的共用前提），再比照本目錄的做法：
一份模板檔＋在上方「目前的模板」表格登記一行，不要另外發明模板的目錄結構或命名慣例。
